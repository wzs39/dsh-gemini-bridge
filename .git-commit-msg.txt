revert(tools): subagent as tool-call ended the main session; label it instead

The previous patch made dsh-agy-link emit subagent steps as agy_subagent
tool-call blocks so they would render as cards. That was wrong at the protocol
level and it ended the main session whenever a subagent ran. Chain:

  1. DSH supports exactly three block types -- text / reasoning / tool-call
     (dsh-llm/lib/types/assembler.js).
  2. A tool-call block is queued for EXECUTION, not just display.
  3. The synthetic id "agy-subagent-<run>-<step>" does not parse:
     parseMirrorCallId() only accepts the "agytc-" prefix used by agy_tool.
  4. So DSH held a call it could neither resolve nor execute, and the stream
     closed with finish reason { kind: "stop" }.
  5. DSH read "stop" as "the model finished talking" -> turn over, subagent
     output lost. That is the reported symptom: the main session ends on
     subagent invocation.

Reverted to the original reasoning-block behaviour and fixed only
discoverability, which is all that can be done without a real block type:
the first frame now carries a "── agy subagent (role · state) ──" header and
later frames keep an indent marker, so subagent activity is distinguishable
inside the collapsed reasoning area. No tool-call is ever emitted, so nothing
enters the execution queue and the finish reason stays honest.

Verified on the patched file: zero occurrences of AGY_SUBAGENT_TOOL_NAME and of
"agy-subagent-"; the three remaining tool-call sites are the plugin's own
agy_tool path. node --check clean, bridge suite 88/88.

Adds bridge/tools/repro-finish-missing.mjs, which drives the client through the
four end-of-stream shapes (normal / empty result / in-band error / thinking-only)
and shows that error paths throw instead of emitting a finish -- the invariant
that made the tool-call approach unrecoverable.
